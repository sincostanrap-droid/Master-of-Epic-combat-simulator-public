# 公開手順と掲載範囲

## 2つの掲載範囲

- `web-files.txt`：Pagesに配信する230ファイル。実行用生成データ・技別JSON・ブラウザWorkerと依存先を含みます。
- `github-files.txt`：ソースリポジトリに掲載する候補。上記にREADME・限定テスト・公開設定等を加えた一覧です。
- `web-hashes.json`：配信対象のSHA-256。変更時は内容を確認したうえで該当ハッシュも更新します。CIで自動再選別・自動ハッシュ更新は行いません。`.gitattributes` は配信対象の改行自動変換を止め、Windowsで確認したバイト列をLinux CIでも維持します。

ブラウザ内の最適化Workerと、外部DB取得用Cloudflare Workerは別物です。`worker/` は保守用ソースでありPages成果物には含みません。

## 公開前に行う作業（現在は未実施）

1. ローカルの解析資料・登録構成を保全する。登録構成はブラウザのJSON出力も利用する。
2. GitHub掲載候補と現在の追跡ファイルを比較し、対象外の追跡271件について、ファイルを残したままGitの追跡だけを外す。具体的な対象・コマンド案はローカルの公開選別報告に保存している。まだ実行していない。
3. README等の生成データ内に含まれる出典・根拠メタデータも掲載可否を確認する。ファイル一覧の除外だけでは、必要データ内に埋め込まれた情報までは除去されない。
4. `github-files.txt` にあるものだけを個別にステージし、差分を確認する。`git add .` は使わない。
5. 公開承認後にcommit・pushする。現在はどちらも未実施。
6. GitHubリポジトリの Settings → Pages → Build and deployment → Source を **GitHub Actions** にする。現在のリモート設定は未変更。
7. Actionsの「Reviewed GitHub Pages」を既定ブランチで手動実行する。最初は `publish=false` のまま組立確認だけを行い、確認後に `publish=true` で公開する。

pushでは自動公開しません。公開ジョブは既定ブランチのみ実行可能です。`github-pages` 環境には必要に応じて承認者・対象ブランチを設定してください。

## 動作

ワークフローは新規の `_site` フォルダへ許可一覧だけをコピーし、ファイル名とハッシュを照合します。Git追跡中のファイルに掲載候補外が残っていた場合も停止します。アップロードするのは `_site` のみです。解析資料を含むリポジトリ全体をPages成果物にしません。

ローカルでは次のコマンドで同じ組立を確認できます。

```text
python tools/build-pages.py --output .local-preview/new-release-check
```

追跡の整理後は `--check-git` も指定して確認します。出力フォルダが既にある場合は停止します。自動削除や既存ファイルの上書きは行いません。

## 追跡を外すことと、履歴から消すことの違い

追跡だけを外しても、既存コミットの履歴や公開済みのコピーから資料が消えるわけではありません。未コミット資料の混入防止には掲載候補の個別ステージが必要です。過去の履歴にも載せたくない資料がある場合は、既存履歴を引き継がない公開用リポジトリ等を別途検討します。履歴の書換え・リポジトリ削除・強制pushはこの準備に含めません。

## 検証の範囲

公開用コピーの起動・計算・小規模最適化をローカルの別ポートで確認済みです。Actionsの実行と公開URLでの最終確認は、設定・pushの後に行います。外部サービスの稼働は別途確認が必要です。

設定の根拠：[GitHub公式：カスタムワークフローでのPages公開](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)
